# Лабораторная работа №14. Тестирование приложения

Тесты добавлены к React-проекту Todo-list из лабораторной №8–9 (папка [`task8-9`](../task8-9)). Используются **Vitest**, **React Testing Library**, **jsdom** и `@testing-library/user-event`.

## Запуск

```bash
cd task8-9
npm install
npm test
```

С отчётом о покрытии:

```bash
npm run test:coverage
```

Тесты запускаются без ручной правки кода. Скриншот успешного прогона — [`tests-result.png`](./tests-result.png).

## Что протестировано

Всего **25 тестов в 3 файлах**, все проходят.

### Юнит-тесты логики — `src/utils/todos.test.js` (14 тестов)

- `filterTodos`: фильтр `all`, `active`, `completed`, пустой результат и неизвестный фильтр (fallback на `all`);
- `sortTodos`: сортировка по дате в обе стороны, по алфавиту в обе стороны, fallback для неизвестной сортировки и проверка отсутствия мутации исходного массива;
- `getStats`: обычный список, пустой список и список, где все задачи завершены;
- `createTodo`: создание задачи с обрезанным текстом, флагом `completed` и сгенерированным `id`.

Покрыты обычный случай, краевые случаи (пустой массив, все задачи завершены) и некорректные идентификаторы фильтра/сортировки.

### Тесты компонентов — `src/components/TodoForm.test.jsx`, `TodoItem.test.jsx` (11 тестов)

`TodoForm`:

- рендерятся поле ввода, выбор статуса и кнопка «Добавить»;
- ввод текста и клик вызывают `onAdd` с обрезанным текстом и `completed=false`;
- выборе статуса «Выполненная» передаёт `completed=true`;
- пустая форма не вызывает `onAdd` и показывает ошибку;
- после успешного добавления поле очищается.

`TodoItem`:

- отображаются текст и дата;
- клик по чекбоксу вызывает `onToggle(id)`;
- кнопка «Удалить» вызывает `onDelete(id)` после анимации (проверяется через fake timers);
- редактирование вызывает `onEdit(id, newText)`;
- пустой текст при редактировании не сохраняется и показывает ошибку;
- «Отмена» не вызывает `onEdit`.

По тестируемым модулям:

- `TodoItem.jsx` — 96.77% statements, 100% lines;
- `src/utils/todos.js` — 100% (в отчёте не выводится, потому что полностью покрытые файлы скрываются).

Общий процент ниже, потому что в проект входят компоненты и модули, которые сознательно оставлены без отдельных тестов:

- `App.jsx` — интеграция состояния, `localStorage` и всех обработчиков; это сценарий end-to-end, для него нужен отдельный интеграционный тест;
- `Filters`, `SortControls`, `Stats` — простые презентационные компоненты без собственной логики: значения и обработчики приходят через props;
- `TodoList` — в основном измерение высоты через `useLayoutEffect`, что требует проверки в реальном браузере, а не в jsdom;
- `storage.js` — работа с `localStorage` и защита от повреждённых данных; часть веток проверяется косвенно через `App`, но отдельные тесты не писались, чтобы не дублировать интеграционный сценарий.

## Почему не Zen-Money

В задании лабораторной предложены два варианта: логика «Быков и коров» или Todo-list на React. В репозитории React-Todo-list находится в `task8-9` (в `task10-11` — Zen-Money на чистом JS, в `task12-13` — Next.js). Поэтому тесты добавлены именно к `task8-9`: там есть требуемые компоненты `TodoForm` и `TodoItem` и чистые функции фильтрации/сортировки.
